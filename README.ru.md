# SSpace

3D-редактор гекс-планет для настольных кампаний. Electron + three.js, всё расширяется модами.

[English](README.md) · **Русский**

## Скачать

На странице [Releases](https://github.com/MaksMakovskiy/SSpace/releases) (Windows, без установки — распакуй и запусти `SSpace.exe`):

- **`SSpace-<версия>-win-x64.zip`** — редактор без модов;
- **`SSpace-<версия>-win-x64-full.zip`** — редактор со всеми модами;
- **`*.sspack`** — моды по отдельности: `all-mods.sspack` (все), `themes-pack.sspack` (темы и «Просторный интерфейс»)
  и по файлу на каждый мод. Открой файл в SSpace через «Файл → Открыть…» — моды поставятся и включатся сами
  (если моду нужны другие моды, они уже лежат в том же файле).

## Поделиться проектом, модами и темами

«Файл → Поделиться…» собирает один файл `.sspack`: проект целиком, набор модов, набор тем — или всё вместе
(проект + моды, без которых он не откроется как надо, + твоя тема). Получатель открывает его через
«Файл → Открыть…», видит, что внутри, снимает лишнее и ставит. Моды — это программы: открывай сборки только
от тех, кому доверяешь.

## Сборка из исходников

```
npm install
npm run build     # dist/: голая и полная портативные версии (.zip) и моды (.sspack)
```

## Запуск

Двойной клик по `SSpace.cmd`: при первом запуске он сам поставит зависимости. Или из терминала:

```
npm install
npm start
```

Проверка без окна (печатает консоль редактора и выходит): `npm run smoke`.

### Самопроверка, журнал и метрики

```
npm run selftest          # быстрая: ~20 с, все генераторы, окна, орбита, эффекты, космос, сохранение
npm run selftest:full     # полная: каждый параметр на краях, большие планеты, ~30–60 с
node scripts/selftest.js quick orbit   # только тесты, где в названии есть «orbit»
```

Запуск идёт в отдельном временном профиле (твоя кампания и настройки не трогаются), печатает итог,
выходит с кодом 0 (всё в порядке), 1 (есть ошибки) или 2 (не закончился), полный отчёт — `selftest-report.json`
(тесты, время каждого, метрики, предупреждения из журнала, состояние модов).

В редакторе: «Справка → Журнал и метрики» (Ctrl+9) — живые цифры (FPS, кадр, p95, вызовы отрисовки,
треугольники, память), журнал с фильтром и поиском, таблица замеров (среднее / p95 / максимум) и кнопка
самопроверки. Красный значок ⚠ в строке состояния — в журнале есть ошибки. Десктоп-версия пишет журнал
в файлы `<папка данных>/logs/sspace-ГГГГ-ММ-ДД.log` (14 последних дней), кнопка «Папка логов».

Для модов: `ss.log.info('мой-мод', 'текст', данные)`, `ss.metrics.time('мой-мод:шаг', () => …)`,
`ss.test.register({id, name, run: async (t) => { t.ok(…); t.eq(…); t.budget(мс, норма, '…'); }})` —
тест мода попадёт и в окно, и в `npm run selftest`.

## Папки

| Папка | Что там |
|---|---|
| `app/` | сам редактор (HTML, CSS, модули в `app/src`) |
| `app/packs/base.json` | базовый набор ландшафтов и меток |
| `packs/` | твои наборы — любые `*.json` формата `sspace-pack` |
| `mods/` | моды — папка с `mod.json` и `main.js` |

## Как устроено

Всё содержимое лежит в реестрах `ss.reg.*`: `terrains`, `effects` (GLSL), `textures` (GLSL),
`buildings`, `poiKinds`, `generators`, `tools`, `windows`, `menus`, `packs`.
Встроенный контент регистрируется тем же API, что и моды (`app/src/content/core.js`),
поэтому мод может добавить, заменить или удалить что угодно.

- `ss.hooks.on(name, fn)` — события (`frame`, `doc:loaded`, `doc:changed`, `palette:changed`, `tool:changed`, …) и фильтры (`cellInfo`).
- `ss.patch(obj, 'method', (orig, ...a) => …)` — обернуть любую функцию ядра.
- `ss.THREE`, `ss.scene`, `ss.view`, `ss.doc`, `ss.history`, `ss.ui` — прямой доступ ко всему.

Полный пример со всеми точками расширения: `mods/example-moon/main.js`.

### mod.json

```json
{ "id": "my-mod", "name": "Мой мод", "version": "1.0.0", "main": "main.js",
  "api": 2,                    // версия API SSpace, под которую написан мод
  "requires": ["orbitals"],    // без этих модов не запускается и пишет, что нужно включить
  "optional": ["orbitals"],    // грузится после них, если они включены; работает и без них
  "order": 0 }                 // запасной порядок загрузки (зависимости всегда раньше)
```

Значки — по имени: `icon: 'flame'` (в генераторах, эффектах, объектах орбиты, окнах, кнопках), рисует их текущая тема;
встроенный набор — линейные SVG (`app/src/ui/icons.js`), старые эмодзи сами переводятся в имена.
Тема: `ss.reg.themes.register({id, name, vars: {'--accent': '#…'}, css, icons: {имя: svg|символ}, iconTransform(svg), fx(ss) → очистка})`,
выбор — «Настройки → Тема».

Интерфейс для модов: пункт меню с `bar: {icon, text, side: 'right', active()}` становится кнопкой в верхней панели;
большое окно с разделами слева — `ss.reg.dialogs.register({id, title, icon, sections: [{id, label, icon, render(pane)}]})`
и `ss.ui.openDialog(id, раздел)`; плавающие окна — `ss.reg.windows` (как «Эффекты» и «Орбита»).

В `activate(ss, mod)` есть `mod.has('orbitals')` и `ss.hasMod(id)` — проверить, включён ли другой мод.
Реестры помнят, кто добавил запись (`entry.source`); если мод заменяет чужую запись, это видно в консоли.
Выключенный мод не портит планеты: его объекты на орбите, эффекты, метки и типы остаются в файле
и возвращаются, когда мод снова включат.
Справка внутри редактора: меню «Справка» (F1).

Генератор может задать атмосферу (`atmosphere: {on, color}` или `ctx.atmosphere()`) и «облик» для модов
(`look: {...}` или `ctx.look()`, хранится в `doc.meta.look`). Частицы вокруг планеты по облику:
`ss.particles.forLook('snow', {name, icon, mod, motion: 'fall' | 'rise' | 'orbit' | 'drift', colors, count, …})`.
Все такие эффекты (и флаги без частиц через `ss.particles.addToggle`) попадают в окно «Эффекты» (Ctrl+7),
где их включают и настраивают для каждой планеты: плотность, скорость, размер, яркость, цвет (`doc.meta.fx`).

## Генератор миров

«Генератор миров» (Ctrl+8, «Планета → Генератор миров…») — большая галерея: карточки с настоящим предпросмотром
каждого генератора, поиск и группы; слева настройки выбранного мира, дополнения (обитаемость и т.п.) и вращающийся предпросмотр.
Генератор может описать себя для библиотеки: `icon`, `group`, `desc`, `preview: ['#цвет', …]`.
Параметры: ползунок `{id, name, min, max, value, unit}`, галочка `{type: 'check', value: true}`,
список `{type: 'select', options: [{value, label}]}`; `section: 'Растения'` собирает параметры под заголовок.
Дополнения к генерации (`ss.reg.genLayers.register({id, name, params, run(ctx), confirm(gen)})`) работают поверх любого
генератора: `ctx.out` — результат генератора, его можно менять; `confirm` может спросить подтверждение
(генератор с `inhabited: true` — уже обитаемый мир).
Последняя генерация запоминается в планете (`doc.meta.gen`), Ctrl+G — ещё вариант с теми же настройками.

## Уровни

Вселенная (галактики) → Галактика (ядро из частиц, сектора «кольца × клинья», звёздные системы) →
Звёздная система (звезда, планеты на орбитах) → Планета (редактор гекс-карты).
Между галактиками, системами и планетами рисуются маршруты; их типы лежат в реестре `ss.reg.routeTypes`.

## Файлы

`*.sspace` — файл кампании: вся вселенная вместе с картами планет. Файл одной планеты или старый файл
«Гекс-планеты» при открытии попадает в текущую звёздную систему (или в новую кампанию).

Тестовый запуск при открытом редакторе: задай `SSPACE_USERDATA` (отдельная папка профиля) и `SSPACE_SMOKE=1`.
